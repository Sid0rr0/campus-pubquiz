# Number is its own question type, not a mode of free text

A question whose answer is a number that is correct within a margin is its own `number` question type, not a setting on `free_text`. It was first described as "free text with a number mode", and `match` already carries a per-question setting. But the question type registry gives each type exactly one grading mode, one answer kind, one kahoot rule and one `/guide` note, and number grades fully automatically against its margin while free text leaves misses to the quiz master. A mode on free text would have turned each of those registry fields into "per type, unless the mode is on", and every consumer would have had to branch on it. The editor makes the type switch feel like a mode instead: switching from Free text to Number keeps the prompt, and keeps the answer if it is a number.
